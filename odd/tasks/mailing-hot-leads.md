# CLA-709 — Mailing hot leads

Rank the prospects who reacted best to mailing campaigns and have not contacted us yet, so management can follow up. Epic CLA-709, sub-issues CLA-710 (T0) to CLA-715 (T5). Branch per ticket from `origin/main`; this task's branch is `feat/cla-711-prospect-contact-log`.

## Specs

- **S1** (T0, CLA-710) — Read-only audit of the first campaign before any scoring code: messages, opens, clicks, IP spread, scanner-like clicks, clicked links, prospects per signal level. Results share no e-mail addresses and no IPs.
- **S2** (T1, CLA-711) — "Already contacted" is marked manually by a system user: "por ahora que sea el usuario del sys que lo marque manual". Each mark is a history entry on the prospect: date (not in the future), direction (inbound: the prospect contacted us; outbound: we contacted them), method (phone, email, in person, website form, other), optional note (max 1000 characters), and the user who logged it.
- **S3** (T1) — Who may log and remove contact entries: option "b" — management uses the `admin` role, so `super_admin` and `admin` may; other roles may not. `technician` keeps having no access to Prospects.
- **S4** (T1) — The Prospects list shows the last contact date (sortable) and a "Contacted / Not contacted" filter; the View modal shows the contact history, newest first. Labels in en, nl and fr.
- **S5** (T1) — Removing an entry needs confirmation and leaves the prospect's other entries untouched. The existing View, Edit, Delete and "Start Mailing Campaign" actions keep working.
- **S6** (T2, CLA-712) — Deterministic, explainable engagement score; weights, decay and bot rules in config; AI is not the scorer.
- **S7** (T3, CLA-713) — Hot leads page for management (`admin`), excluding contacted, unsubscribed, suppressed, bounced and complained prospects.
- **S8** (T4, CLA-714) — AI provider and model changeable without code changes: "que sea facil de cambiar de IA y modelo sin afectar al codigo". Gemini by default. User chose option "B": switch from a Filament screen.
  - **S8a** (T4a) — A `TextGenerationProvider` contract (request: task, system instruction, prompt, optional JSON schema; result: text or decoded JSON, provider, model, token usage) with Gemini (new method on `GeminiService`; existing method signatures unchanged, CLA-611), Anthropic (`anthropic-ai/sdk`) and fake drivers. Typed exception on failure, configurable timeout, logs carry provider, model, task, duration and tokens but never the prompt text.
  - **S8b** (T4a) — Per-task provider and model in config, read through `config()` only (CLA-532); a task without its own setting uses `default`; an unknown provider fails closed. Allowed models per provider are a config allowlist.
  - **S8c** (T4b) — Filament page "AI providers" (super_admin and admin only): per task shows the effective provider, model and where they come from; lets the user change them, limited to the allowlist; "Test" sends a minimal prompt to the chosen provider before saving. API keys stay in `.env`: the page never shows or stores them, only whether each provider has one.
  - **S8d** (T4b) — Resolution order: screen setting for the task → config for the task → config default. Settings in a new table `intelligence_ai_task_settings` (task unique, provider, model, updated_by), read on every resolution without a cache (verifier finding: a cache leaves a stale-routing window), so the next AI call uses a saved change without restarts; every real change is recorded with `spatie/laravel-activitylog` (saving the same choice again writes and audits nothing).
  - **S8e** (T4) — `docs/ai/module-contracts.md` (Intelligence): new AI tasks go through `TextGenerationProvider` and send minimal data (no e-mail addresses or phone numbers). The direct Gemini calls and `env()` outside config found during exploration are recorded in `docs/ai/known-risks.md`, not fixed here.
- **S9** (T5, CLA-715) — On-demand AI summary, next step and draft follow-up mail; nothing is sent automatically.
